# Employee E2E — revised mutation-testing plan (PROPOSAL, nothing executed)

Date 2026-11-17 · Source `048ac6a` · Backend `https://api.workflownets.com`
(production). This plan replaces §10 of `docs/employee-e2e-qa-report.md`.

**No write is executed until the owner approves the exact operation IDs below**
(for example "approve M-A1, M-A2, M-E1"). Approval of one ID never covers another.
The collection's safety gate does not recognize this host, so no Collection
Runner is used. Every write is sent one at a time, and each is followed by
read-only checks.

## 0. Scope rules

1. Writes touch **only** these dedicated QA records:
   - project **1 "QA Test Project"** and its sprint **1 "QA Sprint 1"**;
   - **one new task** created by M-A1, referred to below as `{T}`;
   - **one new conversation** created by M-E1, referred to as `{C}`;
   - **one QA meeting**, created by an admin (precondition P3), referred to
     as `{M}`;
   - the **notifications generated by these steps**.
2. Never touched:
   - project 2 and its records, including the Regular Employee's task in
     project 2;
   - task 1 and the other existing tasks;
   - the shared "Team" conversation;
   - existing notifications;
   - the existing meetings 1–6;
   - account settings, passwords and profile images.
3. Statuses stay within `backlog / todo / in_progress`. `in_review` and
   `completed` are **excluded**, because the monthly timesheet is computed
   from tasks in those statuses dated in the month (collection: "Get
   Timesheet Details"). They could change a real timesheet.
4. Task dates use **2026-11-18**. A write into an *approved* timesheet month
   answers 409. The current month's timesheets are `pending`, so this is not
   expected.
5. Text written anywhere starts with `QA-E2E 2026-11-18`. It contains no
   personal data.
6. **Executor:**
   - **Owner (device)** means the owner taps the action in the app on the
     Redmi 8. This is the real end-to-end path.
   - **Claude (API)** means one exact request sent with the stored QA token,
     used only where the app deliberately offers no control (a negative or
     permission probe).
   - Claude verifies every step with read-only GETs and records status
     codes and keys.
7. Stop rule: any unexpected status, or a record outside rule 1 changing,
   stops the run. It is reported, not retried.

## 4. Irreversible operations (summary)

M-A1 (task row until an admin deletes it), M-A2 (notification), M-E2/E3/E4
(messages and file), M-E1 (conversation record), M-F1/F2 (read flags),
M-G1/G3 (participant history), M-H1 (device token revocation, intended).

## 5. What is reported after the run

For each operation ID: executor, request (method + path + body **keys**),
status code, verification result, and PASS/FAIL/BLOCKED. No tokens, emails,
names or amounts. Results go into `docs/employee-e2e-qa-report.md` (new
section), and the Employee E2E stays **not complete** until the device
checklist and the approved scenarios have passed.
